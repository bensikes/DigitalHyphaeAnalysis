Image Analysis Methods 
HS - October 30th, 2025

Microscopy images were uploaded to a shared google drive folder. These image names range from “1.jpg” to “25.jpg” but the identification information for each image is embedded in the full filepath. Images were organized into subfolders by the location of origin of the samples, the date of image capture, a unique sample identification code including metadata information about the plot of origin, date of sampling, sample depth, and experimental treatments. 

The goal is to quantify hyphal object size (area) and total hyphal length (total path length) from images. Each workflow started by reading in the RGB image and then was converted to grayscale using the “Y” channel from the CYMK colorspace. Then the grayscale image underwent a binary segmentation to create a mask of all blue objects in the image since pixel values in the “Y” colorspace of blue objects will be higher than brown objects. This step of using a binary segmentation was added to help remove false positives, like unstained root material. Next, the grayscale image was blurred slightly to help remove small specks of debris from getting picked up during an adaptive threshold called `plantcv.threshold.gaussian` on the blurred grayscale image to detect the edges of objects. The two different masks are combined with a “logical and” step which only keeps pixels which were included in both approaches. The scale bar is usually still present in the image after combining masks so a region of interest gets used to remove that rectangle of pixels from detection. The combined mask is then further cleaned by using `plantcv.fill` to fill in objects below a size threshold. Next an erosion step is used to thin the objects slightly with a small kernel size, which helps disconnect non-hyphal objects in the mask. Other object properties are also used to clean the mask, including the solidity, eccentricity, and length to filter out non-hyphal objects. After mask cleaning, the binary image is used to create a skeletonized version of the hyphae and this single-pixel wide representation of the object can estimate total path length by counting the number of pixels in an object’s skeleton. This is a custom trait that gets saved to the output file with the `add_observation` method of the Outputs class within PlantCV. The clean mask is also used to perform size analysis, which saves out many metrics of object size and shape including the area in pixels. The image analysis workflow was written with PlantCV and batch processing of images was performed by the “plantcv-run-workflow” functionality for parallelization of analysis. Workflows were batch executed over all images for a given site so that the resulting output dataset of traits would include one site per csv file. The workflow also parsed the input images’ file path to store relevant metadata in a separate column of the output for easier connection to other trait data collected from a given sample. Additionally, the objects detected were plotted by outlining them in pink and saved out the annotated image tiled beside the original image (example 1). These images were saved directly into a new google drive folder after processing happened on a laptop (2018 macbook pro, 2.7 GHz Quad-Core Intel Core i7, 16 GB 2133 MHz LPDDR3). The number of images per site ranged from 150 images to over 2100 images, and batch processing times ranged from 7 minutes to just over 3 hours. 


Introduction content: 
PlantCV is a software package containing image analysis tools aimed at making high throughput plant phenotyping more accessible to those without extensive coding background. It’s completely open source and free to use, and aims to provide easy to use functions that are modular. There is no annotation or training required, unlike deep learning models, so a novel image analysis workflow can be written and ready to execute the same day that images are taken.
